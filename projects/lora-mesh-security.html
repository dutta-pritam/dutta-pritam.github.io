LoRa Mesh Network Security

2024–present, Embedded systems, Wireless security, LoRa

An ongoing line of work on LoRa mesh networking at the protocol level, moving between firmware, security testing, and writing it up.

It started with an audit of a flood-relay mesh built on RP2040 boards at 433 MHz, which turned up five protocol bugs and a scalability ceiling around eight nodes. That audit became a full AODV-lite firmware rewrite (lora_mesh_aodv.ino) supporting 30+ nodes, with non-blocking relay queues, routing tables, RERR propagation, and corrected ACK logic.

A related firmware build for the ESP32-C3 Super Mini added AES-256-GCM encryption and Curve25519 ECDH key exchange on top of the AODV routing, with a BLE layer (Nordic UART Service) for connecting a companion Flutter app — including a migration between NimBLE and standard Bluedroid while keeping the app's UUIDs stable.

On the testing side, I built a Python replay-attack harness (replay_test_harness.py) on a Raspberry Pi to validate the firmware's nonce and counter replay-rejection logic, and ran a passive MITM test — a Raspberry Pi 4B with an SX1278 module intercepting traffic between two legitimate Pico + SX1278 nodes at 433 MHz, SF10, BW 125 kHz, CR 4/5 — alongside a packet-delivery-ratio test across distances up to 150 m. That became a conference paper draft, “Security and Performance Evaluation of a LoRa Mesh Network: MITM Attack and Packet Delivery Ratio (PDR).”

I'm now drafting a follow-up paper scoping a forensics-ready, open-source LoRa MANET testbed — reviewing the multi-hop routing and LoRa security landscape, characterizing the AODV-based mesh's attack surface, and proposing a tamper-evident logging layer and a web-based topology and evidence-download dashboard, meant to be released open-source and DIY-buildable.

System Objective & Hardware

The objective of this project is to develop a low-power, long-range, decentralized communication network using LoRa technology designed to operate without internet or cellular infrastructure[cite: 1]. The node hardware architecture relies on the following components:

  • Raspberry Pi Pico[cite: 1].
  • SX1278 (RA-02 LoRa Module)[cite: 1].
  • JDY-25M BLE Module[cite: 1].
  • 18650 Battery and TP4056 Charger[cite: 1].

Routing Protocol

Currently, due to lower hardware complexity and a smaller number of nodes, the system is implemented with a simple naive flooding technique[cite: 1]. In this protocol, every node receives the data and broadcasts it until it reaches the destination node[cite: 1].

Security & Audio Transmission

The network utilizes a robust security stack, including COMSEC (Data Security) utilizing AES-256-GCM Authenticated Encryption and Session Management through Ephemeral ECDH (Curve25519)[cite: 1]. It also supports audio transmission where a mobile Flutter app captures audio, encodes it into compressed speech bits via Codec2, and transfers it to the Raspberry Pi Pico for LoRa transmission[cite: 1].

Applications

This resilient architecture provides multi-hop communication and self-healing mesh networking[cite: 1]. It is well-suited for several critical applications:

  • Disaster and emergency communication[cite: 1].
  • Rural and remote connectivity[cite: 1].
  • Environmental monitoring and telemetry systems[cite: 1].
  • Infrastructure independent communications in Industries[cite: 1].
  • Secured communication in Military[cite: 1].
